## 1. Aturan Komunikasi (The Rules)

Punya koneksi saja tidak cukup — perangkat harus **sepakat soal cara berkomunikasi**. Tiga elemen dasar dalam komunikasi:
- **Source** (pengirim)
- **Destination** (penerima)
- **Channel** (media/jalur komunikasi)

**Protokol** adalah aturan yang mengatur jalannya komunikasi. Aturan ini bisa berbeda-beda tergantung jenis protokolnya, tapi umumnya harus mencakup:
- Pengirim & penerima yang jelas
- Bahasa dan tata bahasa (grammar) yang sama
- Kecepatan dan waktu pengiriman
- Kebutuhan konfirmasi/pengakuan (acknowledgment)

**Kebutuhan protokol jaringan komputer:**
- **Message Encoding** — proses mengubah informasi ke bentuk lain agar bisa dikirim (dan **decoding** untuk membaca kembali di sisi penerima).
- **Message Formatting & Encapsulation** — pesan harus punya format/struktur tertentu, tergantung jenis pesan dan channel yang dipakai.
- **Message Size** — pesan diubah jadi bit, lalu dikodekan jadi sinyal (cahaya, suara, atau listrik) sebelum dikirim.
- **Message Timing** — mencakup:
  - **Flow Control** — mengatur kecepatan/jumlah data yang dikirim.
  - **Response Timeout** — batas waktu tunggu balasan dari tujuan.
  - **Access Method** — menentukan kapan sebuah perangkat boleh mengirim pesan (untuk menghindari *collision*, yaitu ketika 2 perangkat mengirim data bersamaan).
- **Message Delivery Options** — cara pengiriman pesan:
  - **Unicast** — satu ke satu.
  - **Multicast** — satu ke banyak (tidak semua).
  - **Broadcast** — satu ke semua (khusus IPv4, tidak ada di IPv6).

## 2. Protokol (Protocols)

Protokol jaringan bisa diimplementasikan lewat software, hardware, atau keduanya. Jenis-jenis protokol:

| Jenis Protokol | Fungsi |
|---|---|
| Network Communications | Memungkinkan perangkat berkomunikasi lewat jaringan |
| Network Security | Mengamankan data (autentikasi, integritas, enkripsi) |
| Routing | Memungkinkan router bertukar informasi jalur & memilih rute terbaik |
| Service Discovery | Mendeteksi perangkat/layanan secara otomatis |

**Fungsi protokol dalam komunikasi:**
| Fungsi | Deskripsi |
|---|---|
| Addressing | Mengenali pengirim & penerima |
| Reliability | Menjamin pengiriman data |
| Flow Control | Menjaga aliran data tetap efisien |
| Sequencing | Memberi label unik pada tiap segmen data |
| Error Detection | Mendeteksi kerusakan data saat transmisi |
| Application Interface | Komunikasi antar-proses aplikasi jaringan |

**Contoh interaksi antar-protokol** (saat mengakses website misalnya):
- **HTTP** — mengatur interaksi web server & client, format konten.
- **TCP** — mengelola percakapan individual, menjamin pengiriman, mengatur flow control.
- **IP** — mengirim pesan dari pengirim ke penerima secara global.
- **Ethernet** — mengirim pesan antar-NIC dalam satu LAN.

## 3. Kumpulan Protokol (Protocol Suites)

**Protocol suite** adalah sekumpulan protokol yang saling terkait untuk menjalankan fungsi komunikasi tertentu. Beberapa protocol suite yang pernah ada:
- **TCP/IP (Internet Protocol Suite)** — paling umum dipakai saat ini, dikelola oleh **IETF**.
- **OSI Protocols** — dikembangkan oleh **ISO** dan **ITU**.
- **AppleTalk** — proprietary milik Apple.
- **Novell NetWare** — proprietary milik Novell.

TCP/IP dianggap **open standard** (bebas dipakai siapa saja) dan **standards-based** (disahkan oleh badan standar untuk menjamin interoperabilitas antar-vendor).

## 4. Organisasi Standar (Standards Organizations)

**Open standard** mendorong interoperabilitas, kompetisi sehat, dan inovasi. Beberapa organisasi penting:

**Standar internet:**
- **ISOC** — mendorong pengembangan internet secara terbuka.
- **IAB** — mengelola & mengembangkan standar internet.
- **IETF** — mengembangkan & memelihara teknologi internet dan TCP/IP.
- **IRTF** — fokus riset jangka panjang seputar internet dan TCP/IP.
- **ICANN** — mengoordinasikan alokasi IP address, manajemen nama domain.
- **IANA** — mengelola alokasi IP address, domain, dan identifier protokol untuk ICANN.

**Standar elektronik & komunikasi:**
- **IEEE** — standar di bidang daya, kesehatan, telekomunikasi, dan jaringan.
- **EIA** — standar kabel listrik, konektor, rak 19-inci untuk perangkat jaringan.
- **TIA** — standar perangkat radio, menara seluler, VoIP, komunikasi satelit.
- **ITU-T** — standar kompresi video, IPTV, komunikasi broadband (misalnya DSL).

## 5. Model Referensi (Reference Models)

Karena cara kerja jaringan itu kompleks, dipakailah **model berlapis (layered model)** agar lebih mudah dipahami. Ada 2 model utama:

**Manfaat model berlapis:**
- Membantu desain protokol (tiap layer punya tugas & antarmuka yang jelas).
- Mendorong kompetisi (produk dari vendor berbeda tetap bisa saling bekerja sama).
- Perubahan di satu layer tidak memengaruhi layer lain.
- Memberi "bahasa bersama" untuk menjelaskan fungsi jaringan.

**Model OSI (7 layer):**
| Layer | Nama | Fungsi |
|---|---|---|
| 7 | Application | Protokol untuk komunikasi antar-proses |
| 6 | Presentation | Representasi data yang seragam antar-aplikasi |
| 5 | Session | Mengelola sesi & pertukaran data |
| 4 | Transport | Segmentasi, transfer, dan penyusunan ulang data |
| 3 | Network | Pertukaran data antar-jaringan |
| 2 | Data Link | Pertukaran frame data lewat media yang sama |
| 1 | Physical | Aktivasi/pengelolaan koneksi fisik |

**Model TCP/IP (4 layer):**
| Layer | Fungsi |
|---|---|
| Application | Merepresentasikan data ke user, termasuk encoding & dialog control |
| Transport | Mendukung komunikasi antar-perangkat lewat jaringan berbeda |
| Internet | Menentukan jalur terbaik lewat jaringan |
| Network Access | Mengontrol hardware & media jaringan |

**Perbandingan:** Model OSI membagi *Network Access* dan *Application layer* dari TCP/IP menjadi beberapa layer lebih detail. TCP/IP tidak menentukan protokol spesifik untuk transmisi lewat media fisik — hal itu dijelaskan di Layer 1 & 2 OSI.

## 6. Enkapsulasi Data (Data Encapsulation)

**Segmenting** — memecah pesan jadi unit-unit lebih kecil. **Multiplexing** — menggabungkan/menyisipkan beberapa aliran data yang sudah disegmentasi. Manfaatnya:
- **Meningkatkan kecepatan** — data besar tetap bisa dikirim tanpa memblokir jalur komunikasi.
- **Meningkatkan efisiensi** — hanya segmen yang gagal terkirim yang perlu dikirim ulang, bukan seluruh data.

**Sequencing** — memberi nomor urut ke tiap segmen agar bisa disusun ulang di sisi penerima. Tugas ini dilakukan oleh **TCP**.

**PDU (Protocol Data Unit)** — nama data berubah di setiap tahap saat melewati layer (dari atas ke bawah):
1. **Data** (Data Stream)
2. **Segment**
3. **Packet**
4. **Frame**
5. **Bits** (Bit Stream)

**Enkapsulasi** — proses dari atas ke bawah: tiap layer menambahkan informasinya sendiri sebelum diteruskan ke layer berikutnya, hingga akhirnya jadi aliran bit.

**De-enkapsulasi** — proses kebalikannya (dari bawah ke atas): tiap layer melepas header-nya sendiri, sampai akhirnya jadi data yang bisa diproses aplikasi.

## 7. Akses Data (Data Access)

**Layer Network (Layer 3)** dan **Layer Data Link (Layer 2)** sama-sama memakai pengalamatan untuk mengirim data, tapi dengan cakupan berbeda:
- **IP Address (Layer 3)** — mengantarkan paket dari sumber asli ke tujuan akhir (bisa lintas jaringan/global).
- **MAC Address (Layer 2)** — mengantarkan frame dari satu NIC ke NIC lain **di jaringan yang sama** (bersifat lokal, per-hop).

**Struktur IP Address:**
- **Network portion** (IPv4) / **Prefix** (IPv6) — menunjukkan grup jaringan.
- **Host portion** (IPv4) / **Interface ID** (IPv6) — mengidentifikasi perangkat spesifik dalam grup tersebut.

**Perangkat di jaringan yang sama:**
Jika network portion IP sumber dan tujuan sama, MAC address tujuan langsung memakai MAC address perangkat aslinya.

**Perangkat di jaringan berbeda (remote):**
Jika network portion berbeda, Layer 3 akan mengirim data ke **default gateway** (alamat IP router) terlebih dahulu. Router inilah yang kemudian meneruskan data ke tujuan sebenarnya.

Poin penting:
- **MAC address (Layer 2) berubah di setiap hop** (segmen perjalanan), karena bersifat lokal.
- **IP address (Layer 3) tetap sama** dari awal sampai akhir, karena tujuannya bersifat global/tidak berubah.

Analogi sederhana: IP address itu seperti alamat tujuan akhir di tiket pesawat (misalnya kota C), sedangkan MAC address itu seperti nomor gerbang keberangkatan di setiap transit (kota A → gerbang B → gerbang C) — berubah-ubah di setiap "etape" perjalanan.

## Poin-Poin Kunci (Ringkasan Singkat)

- Komunikasi jaringan butuh **protokol** yang disepakati bersama (pengirim, penerima, format, kecepatan, dsb).
- **Protocol suite** adalah kumpulan protokol yang saling bekerja sama — **TCP/IP** adalah yang paling umum dipakai saat ini.
- **Open standard** (dikelola organisasi seperti IETF, IEEE, ICANN, dll) mendorong interoperabilitas antar-vendor.
- Ada 2 model referensi jaringan: **OSI (7 layer)** dan **TCP/IP (4 layer)**.
- **Data encapsulation** mengubah data lewat 5 tahap PDU: **Data → Segment → Packet → Frame → Bits**.
- **Layer 3 (IP address)** menangani pengiriman data secara global/end-to-end, sedangkan **Layer 2 (MAC address)** menangani pengiriman lokal per-hop.

## Istilah Penting

| Istilah | Arti Singkat |
|---|---|
| Protocol | Aturan yang mengatur komunikasi jaringan |
| Protocol Suite | Kumpulan protokol yang saling terkait |

| TCP/IP Model | Model referensi 4 layer |

| Default Gateway | Alamat router yang jadi pintu keluar ke jaringan lain |
| MAC Address | Alamat fisik NIC, dipakai untuk pengalamatan lokal (Layer 2) |
| IP Address | Alamat logis, dipakai untuk pengalamatan global (Layer 3) |
| HTTP, TCP, IP, Ethernet | Contoh protokol yang bekerja bersama saat mengakses web |
| IETF, IEEE, ICANN, IANA | Contoh organisasi pengembang standar jaringan |
